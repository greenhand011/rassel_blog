# 误差传播实战：当密文遭遇比特翻转

在实际的网络传输中，数据可能会因为干扰产生位翻转（Bit-flip）。对于加密数据来说，这种微小的损坏在解密时可能会产生放大的破坏效应。这就是所谓的**误差传播（Error Propagation）**。

在此篇博客中，我们将通过“破坏”密文中的第 28 个字节，观察五种主流加密模式的抗风险能力。

---

## 1. 核心原理：五大模式的误差传播特性

在分析实验结果前，我们先从数学公式预测结果（假设每个块大小为 16 字节）：

| 模式    | 误差传播原理简述                                                                          | 预期损坏范围                           |
| :------ | :---------------------------------------------------------------------------------------- | :------------------------------------- |
| **ECB** | 块与块之间完全独立。                                                                      | 仅损坏对应的一个明文块。               |
| **CBC** | $P_i = D_K(C_i) \oplus C_{i-1}$。如果 $C_i$ 损坏，会影响当前的 $P_i$ 和下一个 $P_{i+1}$。 | $P_i$ 全毁，$P_{i+1}$ 损坏一个对应位。 |
| **CFB** | $P_i = C_i \oplus E_K(C_{i-1})$。如果 $C_i$ 损坏，会影响 $P_i$ 和 $P_{i+1}$。             | $P_i$ 损坏一个对应位，$P_{i+1}$ 全毁。 |
| **OFB** | 密钥流与密文无关。$P_i = C_i \oplus \text{KeyStream}_i$。                                 | 仅在明文对应位损坏 1 bit。             |
| **CTR** | 也是流加密。$P_i = C_i \oplus E_K(\text{Counter}_i)$。                                    | 仅在明文对应位损坏 1 bit。             |

## 2. 实验步骤 (SEED Ubuntu VM)

### 第一步：准备 64 字节的测试文件

我们需要一个足够长的文件（至少 4 个 AES 块，每块 16 字节）。

```bash
# 创建一个 64 字节的纯文本文件
echo "1234567890123456123456789012345612345678901234561234567890123456" > plain.txt
```

### 第二步：加密与人工损坏

我们以 **CBC** 模式为例进行演示（其他模式只需更换命令中的模式后缀）：

```bash
# 1. 加密文件
openssl enc -aes-128-cbc -e -in plain.txt -out cipher_cbc.bin -K 00112233445566778899aabbccddeeff -iv 01020304050607080102030405060708

# 2. 修改密文的第 28 个字节
# 第 28 字节属于第 2 个块 (16 < 28 <= 32)
ghex cipher_cbc.bin
```

*(提示：在 GHex 中找到偏移量为 0x1B (即 27，起始位 0) 的地方，随便改动一个数值并保存)*

### 第三步：解密与结果分析

```bash
# 解密损坏的密文
openssl enc -aes-128-cbc -d -in cipher_cbc.bin -out plain_decrypted.txt -K 00112233445566778899aabbccddeeff -iv 01020304050607080102030405060708

# 查看解密后的结果
cat plain_decrypted.txt
```

## 3. 结果详述：你能恢复多少信息？

通过对五种模式重复上述步骤，你会得到以下结论：

### 1. ECB 模式

- **现象：** 第 17-32 字节（第二个块）完全变成乱码，但第 1-16 字节和 33 字节以后的内容完好无损。
- **恢复程度：** 75% 左右。

### 2. CBC 模式 (最有趣的结果)

- **现象：**
  - 第 2 个明文块（损坏位所在的块）**全部变成乱码**。
  - 第 3 个明文块的第 12 个字节（28 - 16 = 12）**损坏了一个 bit**。
  - 第 1 块和第 4 块完全正常。
- **原理：** $C_2$ 的损坏导致 $D_K(C_2)$ 结果全错，同时它作为 $P_3$ 的 XOR 输入，只影响了 $P_3$ 对应的那个位。

### 3. CFB 模式

- **现象：** 第 2 个明文块损坏了 1 bit，但第 3 个明文块**全部变成乱码**。
- **恢复程度：** 类似 CBC，损坏波及两个块。

### 4. OFB & CTR 模式 (流加密特性)

- **现象：** 解密后的文件，只有第 28 个字节对应的位置坏了 1 bit。其他 63.9 个字节全部正确！
- **恢复程度：** 极高（接近 100%）。
- **优点：** 误差不传播。

---

## 4. 总结与安全启示

- **如果你的网络环境非常不稳定（丢包或位翻转多）**：OFB 和 CTR 模式在数据恢复方面表现最好。
- **如果你的安全性要求高（不希望攻击者通过微调密文来预测明文）**：CBC 和 CFB 的误差传播特性反而是一种安全保障，因为微小的篡改会导致后续解密失败或出现明显的乱码。
