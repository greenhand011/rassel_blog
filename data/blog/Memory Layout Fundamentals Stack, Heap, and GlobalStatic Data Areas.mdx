# 按生命周期分内存

> 变量活多久，决定它大概率在哪块内存。

## 变量的分类

程序里的变量可以分为三类

1. **函数执行时临时存在**

```c
void func(){
    int a = 10;
}
```

`a`只存在在这个func函数里，所以它是临时变量，**临时变量**通常放在**栈**

2. **程序运行期间一直存在**

```c
int g = 100;
```

```c
void func() {
    static int count = 0;
}
```

生命周期贯穿整个程序的运行期,这类变量就是**全局变量**或**静态变量**这一类长期存活的数据

3. **运行时额外申请出来**

```c
int *p = malloc(sizeof(int));
```

它不是函数天然自带的，它是程序运行过程中“额外要了一块地方”。
这种属于**堆**

当然在这个例子里：

```c
int *p = malloc(sizeof(int));
```

我们能看到两个东西，一个是`p`他是局部变量，所以他本身被归类为`1`临时变量类
而`malloc`申请出来的的空间是`3`动态申请类
也就是说：

> **`p`是栈上的变量，`malloc(...)`是堆上的内存，指针变量自己在哪，和它指向的内存在哪，不一定一样。**

## 分类对应的内存区域

1. **临时变量类 → 栈**

   > - 普通局部变量
   > - 函数参数
   > - 一部分函数调用现场信息

2. **动态申请类 → 堆**

   > - malloc
   > - calloc
   > - realloc
   > - new
   >   申请出来的那块空间

3. **长期存活类 → 全局区 / 静态区**
   > - 全局变量
   > - static 变量

# 在Unbuntu打印出不同变量的地址

先还是按我们之前的习惯创建一个用于今天实验的文件夹

```bash
mkdir -p ~/d2_memory
cd ~/d2_memory
```

创建代码文件，打印三类变量的地址

```bash
nano mem_layout.c
```

```c
#include <stdio.h>
#include <stdlib.h>

int g_var = 10;              // 全局变量
static int s_var = 20;       // 静态全局变量

void func(void) {
    int local_var = 30;                      // 局部变量（栈）
    static int local_static = 40;            // 静态局部变量
    int *heap_var = malloc(sizeof(int));     // 堆内存
    if (heap_var == NULL) {
        printf("malloc failed\n");
        return;
    }

    *heap_var = 50;

    printf("g_var          address: %p\n", (void *)&g_var);
    printf("s_var          address: %p\n", (void *)&s_var);
    printf("local_static   address: %p\n", (void *)&local_static);
    printf("local_var      address: %p\n", (void *)&local_var);
    printf("heap_var(ptr)  address: %p\n", (void *)&heap_var);
    printf("heap memory    address: %p\n", (void *)heap_var);

    free(heap_var);
}

int main(void) {
    func();
    return 0;
}
```

保存并退出
编译

```bash
gcc -Wall -Wextra -o mem_layout mem_layout.c
```

> -Wall -Wextra：打开常见警告

```bash
./mem_layout
```

# 内存布局图

<img src="/static/images/Linux_study/pic_mem.png" alt="内存布局图" width="700" />#
把“全局/静态区”升级成 .data 和 .bss 前面我们说了全局变量和静态区，这都属于长期存活类 再次细分： -
**已初始化的长期变量**通常放进 **.data** - **未初始化，或者初始化为 0 的长期变量**通常放进 **.bss**

## **为什么要分.bss和.data呢？？？**

.data里的变量有明确初始值，这些变量必须真的存到可执行文件里。
.bss里面的变量没有手动初始化，或者就是 0，这类变量没必要在可执行文件里一个个写满 0，**系统加载程序时，直接给这块区域清零就行。**

> **.bss 的存在，是为了节省可执行文件空间。**
