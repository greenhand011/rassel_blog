# 密码学实验室：探究 AES 工作模式的安全边界

在现代网络安全中，选择一种强大的加密算法（如 AES）只是成功的一半。如何“使用”这种算法——即选择哪种**工作模式（Mode of Operation）**——往往决定了系统的真实安全强度。

今天我们将深入探讨 **Scenario 1**：当两个明文消息只有第一个块不同时，不同的加密模式会产生怎样的连锁反应？

---

## 1. 理论先行：块加密模式的数学逻辑

假设我们有两组明文：

- $M_1 = m_1 || m_2 || \dots || m_n$
- $M_2 = m'_1 || m_2 || \dots || m_n$
  （注：$m_1 \neq m'_1$，但后续的所有 $m_2 \dots m_n$ 完全相同）

### Q1: ECB (Electronic Codebook) 模式

**原理：** 每个明文块独立加密，公式为 $C_i = E_K(m_i)$。
**分析：** 因为加密过程不考虑上下文，相同的明文块 $m_2$ 在两组密文中都会生成相同的 $C_2$。
**结论：** Q1 错误。密文块会大量重复，泄露了明文的结构信息。

/>

### Q2: CBC (Cipher Block Chaining) 模式

**原理：** 每个明文块在加密前先与前一个密文块异或，公式为 $C_i = E_K(m_i \oplus C_{i-1})$。
**分析：** 虽然 $m_2$ 相同，但在 $M_1$ 中它异或的是 $C_1$，而在 $M_2$ 中它异或的是 $C'_1$。因为 $C_1 \neq C'_1$，导致后续所有的密文块都会完全不同。这就是**雪崩效应（Diffusion）**。
**结论：** Q2 正确。密文块不会重复。

<img
  src="/static/images/course/theory-cbc-chain.png"
  alt="CBC 模式原理图：展示密文块如何链接"
  width="700"
/>

### Q3 & Q4: CTR (Counter) 模式

**原理：** 将加密算法当作流加密器。加密一个递增的计数器（Nonce + Counter），然后与明文异或。公式为 $C_i = m_i \oplus E_K(\text{Counter}_i)$。
**分析：**

- **Q3（相同 IV/Nonce）：** 如果 IV 相同，生成的密钥流（Keystream） $E_K(\text{Counter})$ 就完全相同。此时 $C_2 = m_2 \oplus \text{KeyStream}_2$，密文块必然重复。
- **Q4（唯一 IV）：** 不同的 IV 生成不同的密钥流，即使明文相同，密文也会完全不同。
  **结论：** Q3 错误，Q4 正确。

## 3. 手把手实验步骤

### 第一步：创建测试明文

我们需要手动创建两个文件，确保它们只有前 16 个字节（AES 的一个块大小）不同。

```bash
# 进入桌面创建一个实验文件夹
cd ~/Desktop && mkdir crypto_lab && cd crypto_lab

# 创建 M1 (Student ID: 11335577)
echo "11335577 is my student ID. This part is common for both files." > f1.txt

# 创建 M2 (Student ID: 22446688)
echo "22446688 is my student ID. This part is common for both files." > f2.txt

# 确认文件内容
cat f1.txt
cat f2.txt
```

### 第二步：验证 ECB 的缺陷

执行加密并观察密文。

```bash
# 使用 AES-128-ECB 加密，不填 IV（ECB 不需要 IV）
openssl enc -aes-128-ecb -e -in f1.txt -out f1_ecb.bin -K 00112233445566778899aabbccddeeff
openssl enc -aes-128-ecb -e -in f2.txt -out f2_ecb.bin -K 00112233445566778899aabbccddeeff

#openssl enc -aes-128-ecb -e：用 AES-128 的 ECB 模式进行加密
#-in / -out：输入文件 → 输出密文文件
#-K 0011...eeff：直接指定十六进制对称密钥

# 使用 xxd 比较密文
xxd f1_ecb.bin
xxd f2_ecb.bin

#xxd 是把文件的二进制内容以十六进制（hex）形式打印出来，方便人看和分析的工具。

```

**实验现象：** 你会看到第一行之后的十六进制编码完全一样！这证明了 ECB 无法隐藏重复的明文块。

### 第三步：验证 CBC 的雪崩效应

使用相同的密钥和相同的初始向量（IV）。

```bash
# 使用相同的 K 和 iv
openssl enc -aes-128-cbc -e -in f1.txt -out f1_cbc.bin -K 00112233445566778899aabbccddeeff -iv 01020304050607080102030405060708
openssl enc -aes-128-cbc -e -in f2.txt -out f2_cbc.bin -K 00112233445566778899aabbccddeeff -iv 01020304050607080102030405060708

#IV（Initialization Vector，初始化向量）是 CBC 模式里用来“打乱第一块加密起点”的随机值，防止相同明文在相同密钥下产生相同密文。

# 比较密文
xxd f1_cbc.bin
xxd f2_cbc.bin
```

**实验现象：** 尽管 $M_1$ 和 $M_2$ 大部分相同，但 CBC 生成的密文从头到尾彻底不同。

### 第四步：验证 CTR 的计数器重用危机

**Q3（相同 IV）：**

```bash
openssl enc -aes-128-ctr -e -in f1.txt -out f1_ctr_same.bin -K 00112233445566778899aabbccddeeff -iv 01020304050607080102030405060708
openssl enc -aes-128-ctr -e -in f2.txt -out f2_ctr_same.bin -K 00112233445566778899aabbccddeeff -iv 01020304050607080102030405060708
xxd f1_ctr_same.bin
xxd f2_ctr_same.bin
```

**实验现象：** 密文再次出现了部分重复。这在流加密中极其危险（Two-Time Pad 攻击）。

**Q4（唯一 IV）：**
修改 `-iv` 参数为另一个值，你会发现密文恢复了多样性。

---

## 4. 总结

| 加密模式 | 扩散性 (Diffusion) | 是否建议使用 | 备注                       |
| :------- | :----------------- | :----------- | :------------------------- |
| **ECB**  | 无                 | **绝不建议** | 容易受到重放攻击和统计分析 |
| **CBC**  | 强                 | **建议**     | 必须确保 IV 唯一且不可预测 |
| **CTR**  | 强 (依赖 IV)       | **建议**     | **绝对不能**重用 Nonce/IV  |

通过本次实验，我们验证了：在密码学中，**扩散性**是衡量一种加密模式安全性的重要指标。CBC 通过链式反馈实现了优秀的扩散，而 CTR 则高度依赖 IV 的唯一性。
