# 数组不是指针

“数组不是指针”这个标题一打眼上去感觉像废话，但确实是很多初学者容易犯的错
来看这段代码

```c
char arr[] = "abc";
char *p = arr;
```

会不会有人觉得`arr`是指针`p`也是指针,所以它们是一样的
**错错错！！！**
来看看他们各自是什么！

1. **`arr`**

```c
char arr[] = "abc";
```

这句话的意思是,在内存里，真的创建出一块连续空间：

```c
'a' 'b' 'c' '\0'
```

所以`arr`是**一整个字符数组**

2. **`p`**

```c
char *p = arr;
```

这句话的意思是创建一个变量`p`，它里面存的是地址，指向 arr[0],所以 `p` 是**一个指针变量**

## 为什么容易混淆

大家看到都可以这样访问的时候

```c
arr[0]
p[0]
```

就觉得可能都一样
但是要记住他们的本质不一样，这就好比：

> 你站在柜子前拿第 1 个盒子
> 你拿着地址找到柜子再拿第 1 个盒子

最后都能拿到盒子，
但你本人和地址纸条不是一个东西。

# 为什么 ptr++ 可以，而 name++ 不可以

上面我们说

- 数组不是指针
- 数组名会退化成地址
  现在我们直接看代码

```c
char name[] = "ecu";
char *ptr = name;

ptr++;    // 可以
name++;   // 不可以
```

`ptr` 是一个变量,它里面存的是地址,既然它是变量，那么它里面存的值就可以改。
比如本来：

```c
ptr -> &name[0]
```

执行：

```c
ptr++;
```

以后，它就变成：

```c
ptr -> &name[1]
```

也就是从指向 'e'，变成指向 'c',所以 ptr++ 的本质是让这个地址变量往后移动一个字符单位。

`name` 是数组名,数组名不是一个“普通地址变量”,它不是那种你可以随手改值的东西。你可以把它理解成`name` 代表的是“这整块数组本身”而不是一个“专门拿来存地址、并且可以改来改去的变量”。
所以：

```c
name++;
```

不允许。因为你不是在改一个地址变量，你是在试图改“数组名”本身,而数组名不能这样改。

# 为什么 arr[i] 和 p[i] 都能用

```c
arr[1]
p[1]
```

它们访问出来的结果一样
因为在 C 里

```c
arr[i]
```

本质上等于

```c
*(arr + i)
```

又等于

```c
*(&arr[0] + i)
```

```c
p[i]
```

本质上等于

```c
*(p + i)
```

> **arr[i] 和 p[i] 都能用，是因为它们本质上都能变成“地址偏移后取值”。**

# 字符串最后一定有一个 \0

```c
char arr[] = "abc";
```

它在内存里不是 3 个字符，而是 4 个

```c
arr[0] = 'a'
arr[1] = 'b'
arr[2] = 'c'
arr[3] = '\0'
```

## 为什么会多一个 \0

因为在 C 语言里，字符串不是“知道自己长度”的高级对象,C 判断字符串结束，不是靠“长度字段”，而是靠**遇到`\0`就表示结束**

> **`\0`是字符串结束标志**

看这个代码

```c
#include <stdio.h>

int main() {
    char arr[] = "abc";

    printf("%c\n", arr[1]);
    printf("%d\n", arr[3]);

    return 0;
}
```

这里第二行我用 `%d`，因为 \0 打印成数字更容易看。

## 为什么 strlen 和 sizeof 结果经常不一样

> `strlen` **数的是字符串长度，不算**` \0`；`sizeof`**数的是整个数组占了多少字节**。

```c
char s[] = "hi";
```

内存里实际是

```
s[0] = 'h'
s[1] = 'i'
s[2] = '\0'
```

所以这一整块数组，一共占 3 个字节。
**那 `strlen(s)` 是多少?**
strlen 的意思是从开头开始数，数到 \0 为止，但 不把 \0 算进去,所以
`strlen(s) = 2`
因为只有：

1. h
2. i

这两个算字符串内容。
**那 sizeof(s) 是多少**
sizeof 看的是这整个数组对象在内存里占多少字节而 s 这块数组里有：

1. 'h'
2. 'i'
3. '\0'

所以`sizeof(s) = 3`
**这一点很重要！非常重要！**

> 因为很多人会犯这种错：
> “字符串是 5 个字符，那我开 char buf[5] 就够了。”
> 其实不够。
> 因为还要给 \0 留 1 个位置。
> 这就是很多**字符串拷贝越界**的根源。

### 为什么 char buf[3] = "abc"; 是错的

那上面说了那么多，看到这也很明显就知道为什么了，因为有个\0，
所以要么写

```c
char buf[4] = "abc";
```

要么写

```c
char buf[] = "abc";
```

### 为什么数组传进函数后，sizeof 就不再是整个数组大小

看下面这个代码

```c
#include <stdio.h>

void test(char s[]) {
    printf("in test: %zu\n", sizeof(s));
}

int main() {
    char s[] = "abc";
    printf("in main: %zu\n", sizeof(s));
    test(s);
    return 0;
}
```

> %zu 是 C 语言中用于格式化输出 size_t 类型变量的格式说明符

<img src="/static/images/Linux_study/sizeofstrlen.png" alt="数组里外的sizeof" width="700" />

在 main 里

```c
sizeof(s)
```

看到的是整个数组，所以结果是 4。
但传进 test 以后

```c
void test(char s[])
```

这里的 s 已经不是“整个数组”了，而是 指针。
所以这里的`sizeof(s)`看到的是 指针大小，不是数组大小,在 64 位机器上通常是 8。

> **数组一旦传进函数，函数参数里的它就会变成指针。**

## 所以为什么函数参数里要额外传长度

> **因为数组传进函数后会变成指针，所以函数自己不知道这块数据到底有多长。**

```c
void test(char s[]) {
    // 这里只有 s 这个指针
}
```

函数现在手里有什么？**只有一个地址**,它知道,从哪里开始,它不知道,一共有多长?能读到哪里?能写到哪里?
**这就是危险的地方**

> 别人递给你一张纸条，上面写着一个仓库地址。
> 你知道仓库入口在哪。
> 但你不知道这个仓库到底有多长。
> 所以你如果往后一直读、一直写，就可能越界。

这在嵌入式和安全里特别重要
当你拿到

- 一段缓冲区
- 一段报文
- 一段配置数据
- 一段固件内容

如果你只传指针，不传长度，就很容易出问题。

所以真正工程里更常见的是这样写：

```c

void test(char *s, int len) {
}
```

或者：

```c
void test(const char *s, size_t len) {
}
```

意思就是：s 告诉我从哪里开始,len 告诉我我最多能处理多少

# 修改数组的易错点

来看这个代码

```c
char *p = "abc";
p[0] = 'A';
```

**这句很危险**
很多初学者会觉得：p[0] 不就是第一个字符吗改成 'A' 有什么问题
问题很大。

```c
char *p = "abc";
```

不是“创建了一个你自己的可修改数组”。它的意思是`p` 指向字符串字面量 `"abc"`,而这个字符串字面量，通常不应该改。
所以后面这句：
`p[0] = 'A';`

就是在改一块不该改的内存,很多环境下会直接崩掉。
这个不该改的内存是什么，在我之前的博客里我有讲过内存分区，这个不应该改的变量对应的就是`.rodata`**只读存储区**
