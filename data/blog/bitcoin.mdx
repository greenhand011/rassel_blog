## 1. 核心定义：什么是“电子硬币”？

在白皮书第 2 节，中本聪给出了一个反直觉的定义：**比特币不是存储在某个账户里的数字，而是一串数字签名的链条（Chain of Digital Signatures）。**

### 1.1 交易链的数据结构

设想一枚硬币的所有权转移过程。每一笔交易（Transaction, Tx）都包含三个核心部分：

1.  **输入（Input）**：上一笔交易的哈希值（Hash），这不仅是指向来源的指针，更是对历史的“确认”。
2.  **输出（Output）**：接收者的公钥（Public Key），锁定了下一任所有者。
3.  **签名（Signature）**：当前所有者用私钥（Private Key）对前两者的签名。

### 1.2 形式化描述

假设所有者 $A$ 要转币给 $B$。
交易 $Tx_{n}$ 的构成如下：

$$
Tx_n = \text{Sign}_{Sk_A}(\text{Hash}(Tx_{n-1}) + Pk_B)
$$

其中：

- $Sk_A$：A 的私钥。
- $Pk_B$：B 的公钥。
- $Tx_{n-1}$：A 获得这枚币的那笔交易。

### 1.3 致命缺陷：双重支付（Double Spending）

上述模型有一个巨大的漏洞。数字文件可以被无损复制。$A$ 可以构建两笔合法的交易：

1.  $Tx_{n} \rightarrow B$（把钱给 B）
2.  $Tx'_{n} \rightarrow C$（把同一笔钱给 C）

这就产生了**双花**。传统银行通过中心化数据库检查 $Tx_{n-1}$ 是否已被花费。去中心化环境下，我们需要全网对**交易顺序**达成共识。

## 2. 时间戳服务器与工作量证明（PoW）

为了给交易定序，中本聪引入了**时间戳服务器（Timestamp Server）**，并创造性地将其与**工作量证明（Proof-of-Work）**结合。

### 2.1 区块链的物理形态

比特币并未直接给每笔交易打时间戳（那样太慢），而是将多笔交易打包进一个**区块（Block）**。
区块头（Block Header）包含：

1.  上一区块的哈希（Previous Block Hash）。
2.  当前区块所有交易的默克尔根（Merkle Root）。
3.  时间戳（Timestamp）。
4.  随机数（Nonce）。

### 2.2 PoW 的数学不等式

挖矿（Mining）本质上是在寻找一个随机数 $Nonce$，使得区块头的哈希值小于目标值（Target）。

$$
H(\text{Block Header}) \le \text{Target}
$$

其中，$\text{Target}$ 与挖矿难度（Difficulty）成反比：

$$
\text{Target} = \frac{\text{Max Target}}{\text{Difficulty}}
$$

因为 SHA-256 是抗原像攻击（Pre-image resistance）的，且输出看似随机，寻找这个 $Nonce$ 的唯一方法是**暴力穷举**。这构成了物理算力到数字权力的映射。

### 2.3 Python 实战：模拟挖矿算法

让我们抛开枯燥的理论，用 Python 写一个最小化的 PoW 模拟器，感受难度的指数级变化。

```python
import hashlib
import time

def mine_block(block_number, transactions, previous_hash, difficulty):
    """
    模拟挖矿过程
    difficulty: 前面需要有多少个0
    """
    prefix_zeros = '0' * difficulty
    nonce = 0
    start_time = time.time()

    while True:
        # 拼接区块头数据
        text = str(block_number) + transactions + previous_hash + str(nonce)
        # 计算哈希
        hash_result = hashlib.sha256(text.encode()).hexdigest()

        # 检查是否符合难度要求
        if hash_result.startswith(prefix_zeros):
            end_time = time.time()
            print(f"挖矿成功! Nonce: {nonce}")
            print(f"Hash: {hash_result}")
            print(f"耗时: {end_time - start_time:.4f}秒")
            return hash_result

        nonce += 1

# 实战测试：
# 尝试将 difficulty 从 4 改为 5，你会发现耗时呈指数级增长
last_hash = "0000000000000000000aaabbbccc"
mine_block(1, "A转给B 10BTC", last_hash, 4)
```

**原理总结**：一旦找到满足条件的 Nonce，该区块被广播。其他人验证只需一次哈希计算（$O(1)$），但生成需要亿万次计算。这种**非对称性**是比特币安全的基础。

## 3. 网络与默克尔树（Merkle Tree）优化

### 3.1 默克尔树：空间换时间的极致

白皮书第 7 节 "Reclaiming Disk Space" 提到了修剪旧数据。为什么即使删除了交易数据，还能验证交易存在？因为使用了默克尔树。

默克尔树是一种二叉哈希树。底层的叶子节点是交易的哈希，父节点是两个子节点哈希的哈希。

$$
H_{\text{parent}} = \text{Hash}(H_{\text{left}} || H_{\text{right}})
$$

最终生成的 **Merkle Root** 被写入区块头。

### 3.2 简易支付验证（SPV）

对于手机钱包（轻节点），无需下载几百 GB 的全量数据，只需下载**区块头（Block Header）**。
如果要验证交易 $Tx3$ 是否在区块里：

1.  拿到区块头里的 Merkle Root。
2.  全节点提供一条 **Merkle Path**（图中的蓝色路径：$Hash01$, $Hash2$）。
3.  轻节点自己计算：
    - $Hash3 = Hash(Tx3)$
    - $Hash23 = Hash(Hash2 + Hash3)$
    - $Hash0123 = Hash(Hash01 + Hash23)$
4.  对比计算结果是否等于区块头里的 Root。

### 3.3 Python 实战：构建默克尔根

```python
import hashlib

def get_hash(value):
    return hashlib.sha256(value.encode('utf-8')).hexdigest()

def compute_merkle_root(transactions):
    if len(transactions) == 1:
        return transactions[0]

    new_level = []
    # 两两分组
    for i in range(0, len(transactions), 2):
        left = transactions[i]
        # 如果是奇数个，最后一个复制自己
        right = transactions[i+1] if i+1 < len(transactions) else left
        # 组合哈希
        combined = get_hash(left + right)
        new_level.append(combined)

    return compute_merkle_root(new_level)

txs = ["Tx1", "Tx2", "Tx3", "Tx4"]
tx_hashes = [get_hash(tx) for tx in txs]
root = compute_merkle_root(tx_hashes)
print(f"Merkle Root: {root}")
```

## 4. 深度解析：攻击概率论（Calculations）

这是白皮书第 11 节，也是研究生最需要掌握的数学核心。
**问题**：假设攻击者拥有 $q$ 的算力（$q < 0.5$），诚实节点拥有 $p$ 的算力（$p = 1-q$）。攻击者试图秘密篡改 $z$ 个区块前的交易，他能追上诚实链的概率是多少？

### 4.1 赌徒破产模型（Gambler's Ruin Problem）

这本质上是一个**二项随机游走（Binomial Random Walk）**。

- 诚实节点挖出一个块，攻击者差距 $+1$。
- 攻击者挖出一个块，差距 $-1$。

只要差距归零，攻击者就追上了。
根据随机过程理论，攻击者追上的概率 $q_z$ 为：

$$
q_z = \begin{cases}
1 & \text{if } p \le q \\
(q/p)^z & \text{if } p > q
\end{cases}
$$

**结论**：只要诚实算力 $p > q$，随着落后区块数 $z$ 的增加，攻击者追上的概率呈**指数级下降**。

### 4.2 泊松分布的应用

现实中，挖矿出块的时间是不确定的。假设诚实节点挖出 $z$ 个块花费了平均时间 $T$。在这段时间内，攻击者能挖出多少个块？这是一个服从**泊松分布（Poisson Distribution）**的随机变量。

期望值（Expected value）$\lambda$ 为：

$$
\lambda = z \frac{q}{p}
$$

攻击者最终能反超的概率 $P$，需要对他可能挖出的每一个块数 $k$ 进行累加计算：

$$
P = 1 - \sum_{k=0}^{z} \frac{\lambda^k e^{-\lambda}}{k!} \left( 1 - (q/p)^{(z-k)} \right)
$$

### 4.3 代码模拟验证

为什么中本聪建议等待 6 个确认？让我们用 Python 实现这个公式来看看概率。

```python
import math

def attacker_success_probability(q, z):
    """
    q: 攻击者算力占比 (例如 0.1 代表 10%)
    z: 等待确认的区块数
    """
    p = 1.0 - q
    lamb = z * (q / p)
    sum_prob = 0.0

    for k in range(z + 1):
        poisson = (math.exp(-lamb) * (lamb ** k)) / math.factorial(k)
        # 累加“攻击者永远追不上的概率”
        sum_prob += poisson * (1 - (q / p) ** (z - k))

    return 1 - sum_prob

print("--- 攻击成功概率表 ---")
print(f"攻击者算力 q=10%, 等待 0 个块: {attacker_success_probability(0.1, 0):.6f}")
print(f"攻击者算力 q=10%, 等待 6 个块: {attacker_success_probability(0.1, 6):.6f}")
print(f"攻击者算力 q=30%, 等待 6 个块: {attacker_success_probability(0.3, 6):.6f}")
```

**运行结果解读**：

- 当 $q=0.1$ (10%算力)，等待 6 个区块后，攻击成功率仅为 **0.00024**（万分之二）。
- 这就是为什么交易所通常要求“6个确认”才入账——在数学上这等同于绝对安全。

## 5. 总结

中本聪的白皮书之所以经典，不在于他发明了这一章里用到的某一个具体技术（PoW 也就是 Hashcash，公钥加密早就有，Merkle Tree 也是旧技术），而在于他将这些组件通过**博弈论**和**概率论**完美地组合在了一起。

1.  **数据层**：用哈希链保证了历史不可篡改。
2.  **网络层**：用 Gossip 协议保证了数据传播。
3.  **共识层**：用 PoW 解决了“谁记账”的投票权问题（One CPU, One Vote）。
4.  **激励层**：用挖矿奖励让贪婪的攻击者不得不变为诚实的维护者。
