## 1. 核心定义：什么是“电子硬币”？

在白皮书第 2 节，中本聪给出了一个反直觉的定义：**比特币不是存储在某个账户里的数字，而是一串数字签名的链条（Chain of Digital Signatures）。**

### 1.1 交易链的数据结构

设想一枚硬币的所有权转移过程。每一笔交易（Transaction, Tx）都包含三个核心部分：

1.  **输入（Input）**：上一笔交易的哈希值（Hash），这不仅是指向来源的指针，更是对历史的“确认”。
2.  **输出（Output）**：接收者的公钥（Public Key），锁定了下一任所有者。
3.  **签名（Signature）**：当前所有者用私钥（Private Key）对前两者的签名。

### 1.2 形式化描述

假设所有者 $A$ 要转币给 $B$。
交易 $Tx_{n}$ 的构成如下：

$$
Tx_n = \text{Sign}_{Sk_A}(\text{Hash}(Tx_{n-1}) + Pk_B)
$$

其中：

- $Sk_A$：A 的私钥。
- $Pk_B$：B 的公钥。
- $Tx_{n-1}$：A 获得这枚币的那笔交易。

### 1.3 致命缺陷：双重支付（Double Spending）

上述模型有一个巨大的漏洞。数字文件可以被无损复制。$A$ 可以构建两笔合法的交易：

1.  $Tx_{n} \rightarrow B$（把钱给 B）
2.  $Tx'_{n} \rightarrow C$（把同一笔钱给 C）

这就产生了**双花**。传统银行通过中心化数据库检查 $Tx_{n-1}$ 是否已被花费。去中心化环境下，我们需要全网对**交易顺序**达成共识。

## 2. 时间戳服务器与工作量证明（PoW）

为了给交易定序，中本聪引入了**时间戳服务器（Timestamp Server）**，并创造性地将其与**工作量证明（Proof-of-Work）**结合。

### 2.1 区块链的物理形态

比特币并未直接给每笔交易打时间戳（那样太慢），而是将多笔交易打包进一个**区块（Block）**。
区块头（Block Header）包含：

1.  上一区块的哈希（Previous Block Hash）。
2.  当前区块所有交易的默克尔根（Merkle Root）。
3.  时间戳（Timestamp）。
4.  随机数（Nonce）。

### 2.2 PoW 的数学不等式

挖矿（Mining）本质上是在寻找一个随机数 $Nonce$，使得区块头的哈希值小于目标值（Target）。

$$
H(\text{Block Header}) \le \text{Target}
$$

其中，$\text{Target}$ 与挖矿难度（Difficulty）成反比：

$$
\text{Target} = \frac{\text{Max Target}}{\text{Difficulty}}
$$

因为 SHA-256 是抗原像攻击（Pre-image resistance）的，且输出看似随机，寻找这个 $Nonce$ 的唯一方法是**暴力穷举**。这构成了物理算力到数字权力的映射。

### 2.3 Python 实战：模拟挖矿算法

让我们抛开枯燥的理论，用 Python 写一个最小化的 PoW 模拟器，感受难度的指数级变化。

```python
import hashlib
import time

def mine_block(block_number, transactions, previous_hash, difficulty):
    """
    模拟挖矿过程
    difficulty: 前面需要有多少个0
    """
    prefix_zeros = '0' * difficulty
    nonce = 0
    start_time = time.time()

    while True:
        # 拼接区块头数据
        text = str(block_number) + transactions + previous_hash + str(nonce)
        # 计算哈希
        hash_result = hashlib.sha256(text.encode()).hexdigest()

        # 检查是否符合难度要求
        if hash_result.startswith(prefix_zeros):
            end_time = time.time()
            print(f"挖矿成功! Nonce: {nonce}")
            print(f"Hash: {hash_result}")
            print(f"耗时: {end_time - start_time:.4f}秒")
            return hash_result

        nonce += 1

# 实战测试：
# 尝试将 difficulty 从 4 改为 5，你会发现耗时呈指数级增长
last_hash = "0000000000000000000aaabbbccc"
mine_block(1, "A转给B 10BTC", last_hash, 4)
```

**原理总结**：一旦找到满足条件的 Nonce，该区块被广播。其他人验证只需一次哈希计算（$O(1)$），但生成需要亿万次计算。这种**非对称性**是比特币安全的基础。

## 3. 网络与默克尔树（Merkle Tree）优化

### 3.1 默克尔树：空间换时间的极致

白皮书第 7 节 "Reclaiming Disk Space" 提到了修剪旧数据。为什么即使删除了交易数据，还能验证交易存在？因为使用了默克尔树。

默克尔树是一种二叉哈希树。底层的叶子节点是交易的哈希，父节点是两个子节点哈希的哈希。

$$
H_{\text{parent}} = \text{Hash}(H_{\text{left}} || H_{\text{right}})
$$

最终生成的 **Merkle Root** 被写入区块头。

  width="700"
/>

### 3.2 简易支付验证（SPV）

对于手机钱包（轻节点），无需下载几百 GB 的全量数据，只需下载**区块头（Block Header）**。
如果要验证交易 $Tx3$ 是否在区块里：

1.  拿到区块头里的 Merkle Root。
2.  全节点提供一条 **Merkle Path**（图中的蓝色路径：$Hash01$, $Hash2$）。
3.  轻节点自己计算：
    - $Hash3 = Hash(Tx3)$
    - $Hash23 = Hash(Hash2 + Hash3)$
    - $Hash0123 = Hash(Hash01 + Hash23)$
4.  对比计算结果是否等于区块头里的 Root。

### 3.3 Python 实战：构建默克尔根

```python
import hashlib

def get_hash(value):
    return hashlib.sha256(value.encode('utf-8')).hexdigest()

def compute_merkle_root(transactions):
    if len(transactions) == 1:
        return transactions[0]

    new_level = []
    # 两两分组
    for i in range(0, len(transactions), 2):
        left = transactions[i]
        # 如果是奇数个，最后一个复制自己
        right = transactions[i+1] if i+1 < len(transactions) else left
        # 组合哈希
        combined = get_hash(left + right)
        new_level.append(combined)

    return compute_merkle_root(new_level)

txs = ["Tx1", "Tx2", "Tx3", "Tx4"]
tx_hashes = [get_hash(tx) for tx in txs]
root = compute_merkle_root(tx_hashes)
print(f"Merkle Root: {root}")
```

## 4. 深度解析：攻击概率论（Calculations）

这是白皮书第 11 节，也是研究生最需要掌握的数学核心。这里我们将深入探讨你提出的疑惑：**为什么是这个公式？证明在哪里？**

**问题设定**：
假设攻击者拥有 $q$ 的算力（$q < 0.5$），诚实节点拥有 $p$ 的算力（$p = 1-q$）。攻击者试图秘密篡改 $z$ 个区块前的交易。
此时，诚实链已经领先了 $z$ 个区块。攻击者需要先追上这 $z$ 个区块的差距，然后超过诚实链。

### 4.1 赌徒破产模型（Gambler's Ruin Problem）

**疑问 1：为什么攻击者追上的概率公式是这样的？**

$$
q_z = \begin{cases}
1 & \text{if } p \le q \\
(q/p)^z & \text{if } p > q
\end{cases}
$$

**【数学证明】：**

这本质上是一个**带吸收壁的一维随机游走**问题。
设 $A_n$ 为攻击者在落后 $n$ 个区块时，最终能追平诚实链的概率。

1.  **一步状态转移**：
    攻击者下一步有两种可能：
    *   攻击者挖出一个块（概率 $q$）：落后数变为 $n-1$。
    *   诚实节点挖出一个块（概率 $p$）：落后数变为 $n+1$。

    因此，我们可以列出递归方程：
    $$
    A_n = q \cdot A_{n-1} + p \cdot A_{n+1}
    $$

2.  **边界条件**：
    *   当 $n=0$ 时，攻击者已经追平，概率为 1：$A_0 = 1$。
    *   当 $n \to \infty$ 且 $p > q$ 时，攻击者几乎不可能追上，概率趋向 0：$\lim_{n \to \infty} A_n = 0$。

3.  **求解特征方程**：
    将递归式改写为 $p A_{n+1} - A_n + q A_{n-1} = 0$。
    对应的特征方程为：
    $$
    p x^2 - x + q = 0
    $$
    解这个二次方程：
    $$
    x = \frac{1 \pm \sqrt{1 - 4pq}}{2p}
    $$
    由于 $p+q=1$，我们有 $1 - 4pq = (p+q)^2 - 4pq = (p-q)^2$。
    所以：
    $$
    x = \frac{1 \pm (p-q)}{2p}
    $$
    两个根分别为 $x_1 = 1$ 和 $x_2 = q/p$。

4.  **通解形式**：
    通解为 $A_n = C_1 \cdot (1)^n + C_2 \cdot (q/p)^n = C_1 + C_2(q/p)^n$。

5.  **代入边界条件**：
    *   由 $A_0 = 1$ 得：$C_1 + C_2 = 1$。
    *   由 $\lim_{n \to \infty} A_n = 0$：由于 $p > q$，则 $q/p < 1$，所以 $(q/p)^n \to 0$。为了让极限为 0，必须 $C_1 = 0$。
    *   从而得出 $C_2 = 1$。

    **最终解**：
    $$
    A_z = (q/p)^z
    $$
    这就是攻击者在落后 $z$ 个区块时能追上的概率。

### 4.2 泊松分布的应用

**疑问 2：为什么攻击者挖出的块数服从泊松分布？$\lambda$ 为什么是 $z \cdot (q/p)$？**

在攻击者追赶的过程中，诚实节点并没有停下来。假设诚实节点挖出了 $z$ 个新块，花费了平均时间 $T$。

1.  **泊松分布的适用性**：
    挖矿是一个典型的“泊松过程”（Poisson Process）：事件（挖出块）在时间上是独立的，且在单位时间内发生的平均次数是恒定的。因此，在固定时间段内发生的次数服从泊松分布。

2.  **期望值 $\lambda$ 的推导**：
    假设全网总算力标准化为 1，出块速度为 $R$（比如每 10 分钟 1 个）。
    *   诚实节点的算力为 $p$，出块速度为 $p \cdot R$。
    *   攻击节点的算力为 $q$，出块速度为 $q \cdot R$。

    诚实节点挖出 $z$ 个块所需的时间 $T$ 为：
    $$
    T = \frac{z}{p \cdot R}
    $$

    在这段时间 $T$ 内，攻击者能挖出的块数期望 $\lambda$ 为：
    $$
    \lambda = \text{速度} \times \text{时间} = (q \cdot R) \times T = (q \cdot R) \times \frac{z}{p \cdot R} = z \frac{q}{p}
    $$
    **证毕。**

### 4.3 最终概率公式推导

**疑问 3：这个复杂的求和公式是怎么来的？**

$$
P = 1 - \sum_{k=0}^{z} \frac{\lambda^k e^{-\lambda}}{k!} \left( 1 - (q/p)^{(z-k)} \right)
$$

**推导过程**：

我们需要计算攻击者最终**成功反超**的总概率 $P$。
根据全概率公式，我们可以对攻击者在这段时间内挖出的块数 $k$ 进行分类讨论。

令 $X$ 为攻击者在诚实节点挖出 $z$ 个块期间自己挖出的块数。$X$ 服从泊松分布 $P(X=k) = \frac{\lambda^k e^{-\lambda}}{k!}$。

对于每一个可能的 $k$：
1.  **情况 A ($k > z$)**：攻击者挖出的块比诚实节点多。此时攻击者**直接获胜**，概率为 1。
2.  **情况 B ($k \le z$)**：攻击者挖出的块少于或等于诚实节点。此时，攻击者落后的距离缩短为 $z - k$。根据前面的“赌徒破产模型”，他在落后 $z-k$ 的情况下能追上的概率是 $(q/p)^{z-k}$。

因此，总成功概率 $P$ 为：
$$
P = \sum_{k} P(\text{攻击者挖出 } k \text{ 个块}) \times P(\text{在挖出 } k \text{ 个块的情况下获胜})
$$

拆分为两部分：
$$
P = \sum_{k=z+1}^{\infty} \frac{\lambda^k e^{-\lambda}}{k!} \cdot 1  + \sum_{k=0}^{z} \frac{\lambda^k e^{-\lambda}}{k!} \cdot (q/p)^{z-k}
$$

为了便于计算（因为无穷级数不好算），我们可以利用概率归一性：
$$
\sum_{k=z+1}^{\infty} \dots = 1 - \sum_{k=0}^{z} \frac{\lambda^k e^{-\lambda}}{k!}
$$
把第一部分代入，整理得：
$$
P = 1 - \sum_{k=0}^{z} \frac{\lambda^k e^{-\lambda}}{k!} + \sum_{k=0}^{z} \frac{\lambda^k e^{-\lambda}}{k!} (q/p)^{z-k}
$$
$$
P = 1 - \sum_{k=0}^{z} \frac{\lambda^k e^{-\lambda}}{k!} \left( 1 - (q/p)^{z-k} \right)
$$
**证毕。** 这正是中本聪 C 代码中实现的公式。

### 4.4 代码模拟验证

为什么中本聪建议等待 6 个确认？让我们用 Python 实现这个公式来看看概率。

```python
import math

def attacker_success_probability(q, z):
    """
    计算攻击者在落后 z 个区块时，最终反超的概率。
    q: 攻击者算力占比 (例如 0.1 代表 10%)
    z: 等待确认的区块数
    """
    p = 1.0 - q
    lamb = z * (q / p)
    sum_prob = 0.0
    
    # 这里的 sum_prob 计算的是“攻击者失败的概率”
    # 即：sum( P(挖出k块) * (1 - 追上的概率) )
    for k in range(z + 1):
        poisson = (math.exp(-lamb) * (lamb ** k)) / math.factorial(k)
        # 如果 k <= z，追上的概率是 (q/p)^(z-k)
        # 所以失败的概率是 1 - (q/p)^(z-k)
        catch_up_prob = (q / p) ** (z - k)
        sum_prob += poisson * (1 - catch_up_prob)

    return 1 - sum_prob

print("--- 攻击成功概率表 ---")
print(f"攻击者算力 q=10%, 等待 0 个块: {attacker_success_probability(0.1, 0):.6f}")
print(f"攻击者算力 q=10%, 等待 1 个块: {attacker_success_probability(0.1, 1):.6f}")
print(f"攻击者算力 q=10%, 等待 6 个块: {attacker_success_probability(0.1, 6):.6f}")
print(f"攻击者算力 q=30%, 等待 6 个块: {attacker_success_probability(0.3, 6):.6f}")
print(f"攻击者算力 q=45%, 等待 6 个块: {attacker_success_probability(0.45, 6):.6f}")
```

**运行结果解读**：

- 当 $q=0.1$ (10%算力)，等待 6 个区块后，攻击成功率仅为 **0.00024**（万分之二）。
- 当 $q=0.3$ (30%算力)，等待 6 个区块，成功率跃升至 **0.17** (17%)。这就是为什么对于大额交易，面对高算力潜在攻击者时，需要等待更多确认。
- **6 个确认**是比特币网络为了在兼顾效率（约1小时）和安全（概率极低）之间做出的工程权衡。

## 5. 总结

中本聪的白皮书之所以经典，不在于他发明了这一章里用到的某一个具体技术（PoW 也就是 Hashcash，公钥加密早就有，Merkle Tree 也是旧技术），而在于他将这些组件通过**博弈论**和**概率论**完美地组合在了一起。

1.  **数据层**：用哈希链保证了历史不可篡改。
2.  **网络层**：用 Gossip 协议保证了数据传播。
3.  **共识层**：用 PoW 解决了“谁记账”的投票权问题（One CPU, One Vote）。
4.  **激励层**：用挖矿奖励让贪婪的攻击者不得不变为诚实的维护者。
