# 引言：工欲善其事，必先利其器

在上一篇笔记中，我们把 MIPS 的寄存器比作车间的“收纳盒”。那么，**指令（Instructions）** 就是工位上的“操作动作”。

MIPS 属于 **RISC（精简指令集）** 架构。它的特点是：动作极其简单，甚至有些死板，但执行效率极高。今天，我们就来翻开这本《搬砖工人操作手册》。

---

## 第一部分：MIPS 常用指令速查手册

在 MIPS 的世界里，所有指令长度都是固定的 **32 位**。这种“整齐划一”让 CPU 解析起来飞快。

### 1. 搬运工：lw / sw (Load & Store)

MIPS 是典型的 **Load/Store 架构**，意思是：CPU 不能直接对内存里的数字做加减法，必须先“搬”进寄存器。

- **lw (Load Word):** 把内存里的数据**搬进**寄存器。
  - `lw $t0, 4($sp)`：去栈指针 `$sp` 向上偏移 4 字节的地方，搬一个字（4字节）的数据，放进 `$t0`。
- **sw (Store Word):** 把寄存器里的数据**存回**内存。
  - `sw $t0, 8($sp)`：把 `$t0` 里的数字，存到栈指针偏移 8 字节的内存坑位里。

### 2. 计算器：add / sub / addi

- **add:** `add $t0, $s1, $s2` -> `$t0 = $s1 + $s2`。
- **sub:** `sub $t0, $s1, $s2` -> `$t0 = $s1 - $s2`。
- **addi (Add Immediate):** `addi $t0, $s1, 100`。末尾的 `i` 代表 **Immediate（立即数）**。意思是直接把数字 100 加上去，不需要去寄存器找。

### 3. 裁判员：beq / bne (Branch)

这是写 `if-else` 和循环的核心。

- **beq (Branch if Equal):** 如果相等就跳转。
  - `beq $t0, $t1, label`：如果 `$t0 == $t1`，就跳到 `label` 标签处。
- **bne (Branch if Not Equal):** 如果不相等就跳转。

### 4. 伪装者：li / move (伪指令)

你在汇编代码里经常看到它们，但 CPU 其实并不认识它们。汇编器会将它们转换成真正的指令。

- **li (Load Immediate):** `li $t0, 1`。实际上 CPU 可能会执行 `addiu $t0, $zero, 1`。
- **move:** `move $t0, $t1`。实际上 CPU 执行的是 `addu $t0, $t1, $zero`（还记得 `$zero` 永远是 0 吗？）。

### 5. 呼叫机：jal (Jump And Link)

- **jal:** 跳去子函数，并把“回家的路”记下来。
- **底层动作：**
  1. 跳转到目标地址。
  2. 把跳转指令下一条指令的地址（PC + 4）存入 **$ra** 寄存器。

## 第二部分：核心重难点 —— 延迟槽 (Delay Slot)

这是 MIPS 最让新手崩溃、甚至觉得“反人类”的设计。

### 1. 为什么要搞这一出？（流水线原理）

现代 CPU 执行指令不是一步完成的，而是像**工业流水线**一样分级（通常 5 级）：

1.  **IF (取指)**：从内存拿指令。
2.  **ID (译码)**：弄明白这条指令要干嘛。
3.  **EX (执行)**：真正开始算。
4.  **MEM (访存)**：读写内存。
5.  **WB (写回)**：把结果放回寄存器。

**问题来了：** 当第一条指令在“译码”时，第二条指令已经在“取指”了。
如果你第一条指令是 **`jal`（跳转）**，等到 CPU 弄明白“哦！我要跳走”的时候，**第二条指令已经排在流水线上取出来了！**

### 2. 两种解决方案

- **x86/ARM 的做法：** 发现要跳转了，赶紧把已经取出来的第二条指令扔掉（清空流水线）。但这会浪费一个时钟周期，降低效率。
- **MIPS 的做法：** 既然都取出来了，别浪费，**执行它！**

这就是 **延迟槽 (Delay Slot)**：紧跟在跳转指令（jump/branch）后面的那条指令，**无论跳不跳，它都会被执行。**

### 3. 实战解析：三种写法对比

#### 写法 A：新手/保守派 (使用 nop)

为了不让延迟槽影响逻辑，故意放一个“什么都不做”的占位符。

```assembly
jal big_func    ; 1. 跳转到函数
nop             ; 2. 【延迟槽】空操作。CPU 顺手执行了它，但不产生副作用。
```

#### 写法 B：潜在的 Bug 现场

如果你不知道延迟槽的存在，乱写代码：

```assembly
jal big_func    ; 1. 跳转发生
li  $v0, 0      ; 2. 【延迟槽】这条指令竟然在进入函数前执行了！
                ; 导致结果可能被意外清零。
```

#### 写法 C：极致优化的编译器写法

编译器非常聪明，它会寻找一条本来就要执行的指令，挪到延迟槽里，压榨 CPU 性能。

```assembly
; 源代码逻辑：
; $a0 = 10;
; func();

; 编译器生成的 MIPS 汇编：
jal func        ; 1. 发起跳转
li  $a0, 10     ; 2. 【延迟槽】在跳转生效前，顺手把参数准备好了！
```

**深度总结：** 在 MIPS 中，你看到的顺序是 `jal -> li`，但实际执行逻辑是 `li -> 跳转`。

## 第三部分：给 IOT 安全研究者的建议

当你使用 IDA Pro 或 Ghidra 逆向路由器固件时：

1.  **默认开启延迟槽显示：** 反汇编器通常会提醒你哪条是延迟槽指令。
2.  **重点检查延迟槽里的指令：** 很多漏洞（如溢出后的返回地址覆盖）往往藏在延迟槽的 `lw $ra, ...` 指令里。
3.  **理解 nop 的深意：** 看到大量的 `nop`，说明编译器没有进行深度优化，或者那是为了对齐指令地址。
