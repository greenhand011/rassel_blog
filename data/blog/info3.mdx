# 哈希函数特性解析：单向性与碰撞安全性

在本篇博客中，我们将焦点从“加密”转移到“哈希（Hash）”。哈希函数在完整性校验、数字签名和密码存储中起着至关重要的作用。本实验将通过两个核心任务（H1 和 H2）带你领略哈希函数的魔力与脆弱性。

---

## 任务 H1：理解 SHA256 的雪崩效应 (Avalanche Effect)

一个理想的哈希函数必须具备**雪崩效应**：即输入数据的极其微小变化（哪怕只是一个 bit），都会导致输出的哈希值发生翻天覆地的变化，且看起来毫无关联。

### 1. 实验原理

哈希函数（如 SHA256）通过复杂的位运算和多轮迭代，将输入数据充分“搅拌”。即使输入 $M$ 与 $M'$ 之间只有 1 bit 的差异，经过迭代后，输出 $H(M)$ 与 $H(M')$ 之间约有 50% 的比特位会变得不同。

### 2. 实战步骤

**第一步：创建原始文件**

```bash
echo "Hello, SEED Labs!" > msg.txt
```

**第二步：生成原始哈希值 H1**

```bash
openssl dgst -sha256 msg.txt
```

_(记录下这串 64 位的十六进制字符)_

**第三步：翻转一个比特位 (Flip one bit)**
这是本实验最关键的一步。注意：是翻转 **1 个比特 (bit)**，而不是 1 个字节 (byte)。

- 字节 'H' 的 ASCII 码是 `0x48`，二进制为 `0100 1000`。
- 如果我们将最后一位翻转，变为 `0100 1001`，则对应的字符变为 'I'。
- 或者，你可以使用十六进制编辑器 **ghex** 或 **bless** 直接修改文件中的某一个位。

```bash
# 在终端打开 ghex (如果 VM 已安装)
ghex msg.txt
```

**第四步：生成修改后的哈希值 H2 并对比**

```bash
openssl dgst -sha256 msg_modified.txt
```

**实验观察：**
对比 H1 和 H2，你会发现它们完全不同。这种不可预测性确保了攻击者无法通过微调输入来控制哈希输出。

## 任务 H2：MD5 碰撞与 Merkle-Damgård 结构

虽然 SHA256 目前被认为是安全的，但经典的 **MD5** 算法早已被攻破。

### 1. 理论背景：Merkle-Damgård 构造

大多数现代哈希函数都采用 Merkle-Damgård 结构。它将消息切分为固定大小的块，并使用一个**压缩函数 $f$** 和一个**内部状态 $s$**。

- 属性：如果两个不同的输入 $M$ 和 $N$ 产生了相同的哈希值（即碰撞：$MD5(M) = MD5(N)$），那么在它们后面拼接相同的后缀 $T$ 后，产生的哈希值依然相同。
- 公式表示：$MD5(M || T) = MD5(N || T)$。

### 2. 使用 md5collgen 生成碰撞

我们将使用 `md5collgen` 工具，它可以根据给定的前缀文件，生成两个内容不同但 MD5 哈希值完全相同的文件。

**实战步骤：**

```bash
# 1. 创建一个前缀文件 (Prefix)
echo "This is a secret prefix." > prefix.txt

# 2. 使用工具生成碰撞文件
# -p 指定前缀, -o 指定输出的两个文件
md5collgen -p prefix.txt -o out1.bin out2.bin

# 3. 验证两个文件的内容是否不同
diff out1.bin out2.bin
# (系统会提示 "Binary files out1.bin and out2.bin differ")

# 4. 验证两个文件的 MD5 哈希值是否相同
md5sum out1.bin out2.bin
```

**实验结论：**
你会惊讶地发现，尽管 `out1.bin` 和 `out2.bin` 的内容不一致（工具有意在末尾添加了 128 字节的不同数据），但它们的 `md5sum` 结果竟然**完全一致**！

## 3. 总结与安全性思考

通过本篇博客的两个任务，我们学到了：

1. **SHA256 的稳健性**：微小的改动会引发剧烈的输出变化（H1），使其非常适合用于完整性校验。
2. **MD5 的脆弱性**：利用特定的工具（H2），攻击者可以伪造出具有相同哈希值的不同文件。这也是为什么现在工业界已经弃用 MD5 转而使用 SHA256 或 SHA3 的原因。
