# Blog Style Notes

These notes summarize the tone used by the existing blog posts in this repository.

## Common shape

- Start with a short project-context opening.
- State the day’s goal early.
- Use a “why this matters” paragraph before the implementation details.
- Break the article into small sections with `##` and `###`.
- End with a reflection or next-step paragraph instead of a stiff conclusion.

## What the articles usually feel like

- They read like a real author’s project log, not a lab report.
- The writer often explains the thought process while the system is being built.
- The posts are comfortable mixing implementation, debugging, and security reflection.
- The tone is direct, slightly hard-core, and technical, but still readable.

## Section patterns that work well here

- “今天到底做了什么”
- “先把问题说清楚”
- “为什么要先做这一步”
- “现象 / 原因分析 / 修复方式 / 安全启发”
- “今天的结论”

## Language habits to keep

- Use concrete variable names, command names, and board names.
- Keep paragraphs short enough to scan.
- Use first-person reflection when it helps explain the choice.
- Explain mechanisms before conclusions.

## Things to avoid

- Generic article intros like “本文将介绍...”
- Mechanical checklists without a narrative thread
- Overly formal report tone
- Stacking every image from the folder
- Presenting guessed results as facts

## Image usage pattern

- Place the image right after the paragraph it proves.
- Use one image for one idea whenever possible.
- Prefer the clearest photo or screenshot over a larger set of near-duplicates.
